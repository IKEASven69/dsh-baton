## 对我们的三个动作建议

1. **协议命名尽快占位**：JarvanAI 也喊 "Universal Handoff Protocol"。我们手里有 `handoff: 1` 版本化协议 + SPEC + 参考实现，应在 agent-handoff 仓 README 顶部把"handoff: 1 是版本化开放协议，本仓是 SPEC"的占位声明做显眼（已有，可加一句"采用本协议的项目请 issue 登记"积累采用列表）。
2. **差异化叙事**：casr/aisle 是"换一家 CLI 原生续跑"，我们是"harness 内接管 + 审计语义（四态账本）+ 收件箱异步接力"——README 竞品段可直说这个区别（10-03 已补：README「竞品与差异化」小节，中英同步）。
3. **跨设备是缺口**：agentctxsync 的跨设备同步是唯一我们没覆盖的维度；~/.handoff 天然可以指向 git 仓库/网盘目录实现跨机——文档一句话即可宣称支持（HANDOFF_HOME 指向同步盘），不用写代码。

- Claude Code / Codex 上游如原生支持跨工具会话导出，属最大风险；截至本日未见（各家 resume 仍是自家 `--resume`）
