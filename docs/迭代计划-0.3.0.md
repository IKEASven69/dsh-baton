## P0 · 通知面板排查（0.2.0 已知项，必须闭环）

**现象**：真机 `/handoff` 推送成功（待取件 4→5），但 `ctx.userQuestions.ask` 的阻塞式问答面板未弹出，ask 走静默降级（推测 NO_PROVIDER）。

**排查路径**：
1. 读宿主客户端 user-questions provider 注册源码（`_dsh-compat-test/node_modules/@deepseek-ai/dsh-client-*`）：确认 ask 挂靠的前提条件——是否要求「当前回合 open」、是否要求 provider 由特定 client 包注册、插件工具执行期间 waterfall 是否可达；
2. 对照规范调用样例 `packages/interaction/tool-ask-user/src/index.ts:81-92` 找差异；
3. **两种结局，都是完成**：
   - 可修 → 修好，真机实拍面板弹出；
   - 确认不可行（如 ask 必须挂靠 open turn 而工具收尾时已闭合）→ 通知降级为**行内新卡高亮**（见 P1-4），并在 CHANGELOG 与 README 写明"通知形态 = 收件箱内高亮，不做弹窗"，删除或保留 ask 代码视结论。

**验收**：真机 `/handoff` 实跑，两种结局任一可见、可复现。
